## Vai trò

| Vai trò | Ai | Ghi chú |
|---|---|---|
| Executor | Agent `claude_local` trên Mac, worktree riêng | Làm issue, báo `crew-commit sha=…` |
| Reviewer | Agent riêng (`metadata.crewRole = "reviewer"`) | Review issue con và issue gốc; không bao giờ là executor |
| Integrator | Agent riêng (`metadata.crewRole = "integrator"`) | Merge cả yêu cầu, test một lần trên cây đã merge, chạy `crew-docs check`, ghi bằng chứng |
| Owner | Người dùng board | Chỉ duyệt cuối trên issue gốc |
| Trợ Lý | R1-3 | Tách issue con; không phải reviewer/integrator |

## Policy

- Issue gốc (yêu cầu): stage `review` (reviewer) → `review` (integrator) → `approval` (owner), `maxReviewRounds: 5`.
- Issue con: stage `review` (reviewer), `maxReviewRounds: 5`; không có stage owner.
- Mọi issue mới nhận policy qua hook H4 ở đầu `issueService.create`: agent chỉ tạo được issue con và luôn nhận template con; board/hệ thống không gửi policy thì nhận template theo loại issue; board gửi policy riêng thì giữ.
- Vòng sửa dùng cơ chế stock: quyết định `changes_requested` thứ 5 của agent giao stage cho owner; quyết định của người reset bộ đếm.

## Gate ép ở server (hook H2, đầu `runUpdate`)

- Agent và tiến trình nền không đổi được stage/participant của `executionPolicy`, không nâng `maxReviewRounds`, không xóa policy.
- Issue chỉ vào `done` khi mọi stage có quyết định `approved` của người khác executor (kể cả quyết định trong chính lệnh ghi), và — nếu policy có stage integrator — có bằng chứng docs hợp lệ.
- Bằng chứng docs: comment của agent integrator, dòng đầu `crew-docs-check commit=<head> range=<base>..<head> exit=<0-3>`, mới hơn quyết định `changes_requested` gần nhất. `exit=0` đạt; `exit=3` (repo chưa `crew-docs init`) cho qua kèm activity `crew.docs_gate.uninitialized`; còn lại chặn. Kiểm cả lúc integrator hoàn tất stage của mình lẫn lúc issue vào `done`.
- Board vẫn ép được `done`; mỗi lần ép khi thiếu điều kiện ghi activity `crew.policy.board_override`.
- Không chặn các ghi `blocked`/`cancelled` (cổng tải, plugin hủy run).

## Retry và runtime

- Run retry (có `retryOfRunId`) kiểm commit trong worktree của run trước kể từ `startedAt − 30s`; có commit thì comment `Crew: lần chạy lại…` để agent kiểm tra và tiếp tục, không làm lại; kiểm lỗi thì run chờ theo hạn chót của cổng tải.
- Cổng tải ghi mốc chờ bền trước khi comment, nên comment lỗi không làm run chờ vô hạn.
- H3 dùng script dự phòng khi `crew-mac stop-run` từ chối root (exit 2).
- Plugin `crew.core` là bundle tự đủ; deploy kiểm `/plugins/crew.core/health`.
