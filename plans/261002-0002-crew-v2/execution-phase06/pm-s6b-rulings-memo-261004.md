## 2. Q1 — Process closure: verb `execute-tree`

**Ruling.** Thêm verb `execute-tree` vào `operation-native.c`, dùng chung toàn bộ ABI/kiểm tra identity với `execute` (`operation-native.c:103-149`), khác ở bốn điểm:

1. Child gọi `setsid()` thay cho `setpgid(0,0)` (`:114`): session id = pgid = pid leader, không controlling terminal (đã có stdin `/dev/null`, không ảnh hưởng uv/python).
2. Trước khi mở gate (`:132`), parent ghi `{stage}/.leader` = `pid start-time` (O_EXCL, qua fd stage) để reconcile sau crash có căn cứ (Q4).
3. Vòng tick (`:135-142`) giữ nguyên kqueue `NOTE_FORK|NOTE_EXIT` + quét byte stage + deadline; thêm mỗi tick một lần `sysctl({CTL_KERN, KERN_PROC, KERN_PROC_SESSION, leader})` đếm thành viên session, ghi `maxSessionSize`. Timeout vẫn `kill(-leader, SIGKILL)` rồi kill từng thành viên session còn lại.
4. Khi leader `NOTE_EXIT`: liệt kê session **ngay** (trước `waitpid`). Thành viên khác leader (kể cả zombie chưa reap) → `survivors = n`, kill từng pid + `kill(-leader,SIGKILL)`, chờ ≤2 s tới khi rỗng. Receipt thêm `mode:"tree"`, `sessionEmptyAtExit`, `survivors`, `maxSessionSize`; `forkObserved`/`treeEmpty` giữ nguyên ngữ nghĩa cũ.

`operations.ts` thêm `executeTree(id, identity, cwd, command, timeoutSeconds)` với luật pass: `treeEmpty && sessionEmptyAtExit && survivors === 0`; `forkObserved` được phép. `execute` cũ không đổi (installer giữ `forks: 'deny'`, `builder.ts:26`). Receipt `ExecutionReceipt` thêm field optional; `formatVersion` giữ 1 vì additive.

**Vì sao đây là cách duy nhất giữ argv.** Trên macOS `NOTE_TRACK/NOTE_CHILD` "no longer supported as of 10.5" (`sys/event.h:357-362` của SDK), nên không thể để kernel tự theo dõi hậu duệ; `KERN_PROC_SESSION` (`sys/sysctl.h:439`) là bằng chứng kernel còn lại. `uv run` luôn spawn interpreter (đo `getppid()`, review :10) — không có cờ nào bắt uv `exec`. Gọi `python3 render_skill.py` trực tiếp: (i) `witness.argv` lệch lời gọi chính thức mà runtime sẽ gọi (A5.4, `SKILL.md:9`); (ii) bỏ kiểm `requires-python` của uv; (iii) làm `uvSha256` trong witness vô nghĩa. Bác.

**Phần dư (ghi docs, không sửa).** Hậu duệ tự `setsid()` giữa hai tick thì rời session và không nhìn thấy được; không có cách chứng minh phủ định với công cụ kernel còn lại. Chấp nhận vì renderer đã pin là stdlib thuần không `subprocess` (`render_skill.py:9-23`), uv không setsid, và profile Seatbelt + D1 inspector vẫn bắt output giả. Đây cùng lớp với TOCTOU hash→exec của `uv` đã chấp nhận ở S6a M3.

**Ownership.** `operation-native.c` và `operations.ts` thuộc phase03 (flow `gateway-workflows`, `docs/flows.yaml:252-253`; tạo ở `b1172c8`). Transfer cho S6b **giới hạn**: thêm verb + `executeTree` + sửa N5 (exit 20 trước fork → `EXECUTOR_BUSY`, không giữ stage). `NativeHelper.build` băm source C (`native.ts:31`) nên binary đổi cho cả installer → regression `workflow-operations.test.ts` + registry tests là bắt buộc; phase03-owner review diff C.

**Hệ quả bắt buộc ở workspace.** `IsolationWorkspace.verify` từ chối mọi command có `forkObserved` (`workspace.ts:547-551`). Receipt tree **không được** ghi dưới `command-*`; ghi record riêng `render-{operationId}` (xem Q4) và `verify` thêm luật: mọi `render-*` của attempt phải `complete` với `closure: 'proven'`.

## 3. Q2 — Python ≥3.11 không đổi argv

**Ruling.**

- **Cơ chế:** executor thêm `UV_PYTHON=<realpath interpreter>` vào lớp `/usr/bin/env` (`render-executor.ts:594-598`). Doc uv: "`UV_PYTHON`: Equivalent to the `--python` argument. If set to a path, uv will use this Python interpreter for all operations." Giữ `UV_OFFLINE=1 UV_NO_CONFIG=1 UV_PYTHON_DOWNLOADS=never`. Không dùng `UV_PYTHON_INSTALL_DIR` (uv tự chọn trong nhiều interpreter → không ghim được, quét nhiều binary = nhiều fork hơn, phụ thuộc trạng thái uv của owner).
- **Nguồn interpreter = install report.** Khi gateway làm install report BMAD (`gateway-sync.ts:188-226`), chạy trong **môi trường owner** (không sandbox, cùng lớp với đọc `claude --version` của phase04): `uv python find --script <projectionRoot>/_bmad/scripts/render_skill.py` (cờ `--script` có ở uv 0.12.13, đã kiểm `--help`) → path; `realpath`; sha256 bytes; `<realpath> -c 'import sys;print(sys.version.split()[0])'` → version. Ghi `prerequisites: {uv: {path, realpath, sha256, version}, python: {path, realpath, sha256, version}}` vào `workflow_status.bmad.projections[runtime]` (additive, cạnh `definition`; `definitionMatches` ở `service.ts:289-300` không đọc field này nên không ảnh hưởng `same()`/`body_hash`). Vì `uv python find --script` chọn đúng interpreter mà `uv run` của **runtime** sẽ chọn trong môi trường owner, hai lần render (Crew và runtime) dùng cùng Python — đây là lý do chọn probe này thay vì cấu hình tay.
- **Executor trước spawn:** `realpath(python) === prerequisites.python.realpath`, `lexicalPath`, `digestFile` ≤256 MiB khớp sha256 (đúng kiểu `uv`, S6a M3); lệch → `RENDER_PYTHON_UNAVAILABLE`, không spawn.
- **Witness (sửa A5.2, additive):** `witness.python = {path, sha256, version}`; `uvVersion`/`python.version` là pass-through từ install report (ghi rõ như N4). Server latch so `witness.uvSha256` và `witness.python.sha256` với `gateway_applied` prerequisites của máy (A5.4 "receipt phải khớp install report" — hiện `latchRenderedArtifact` chưa so, `runs.ts:421-472`).
- **Không bind Python vào identity generation.** `identity = {project_root, renderer_sha256, resolved_values, source_sha256}` (`render_skill.py:351-356`); không có phiên bản Python. Vì vậy runtime dùng Python ≥3.11 khác vẫn ra cùng `generation_hash` và `_publish` thấy byte-identical, không ghi đè. Python identity là nhân chứng/chẩn đoán, không phải điều kiện khớp.

**Giới hạn thật thà.** sha256 của binary Python (stub framework hoặc symlink Homebrew → Cellar) **không** ghim stdlib; đó là nhân chứng yếu, chấp nhận được vì D1 inspector xác minh toàn bộ bytes output. Chưa xác minh bằng chạy thật rằng uv kiểm `requires-python` với path tường minh (doc không nói rõ); nếu không kiểm thì Python <3.11 vẫn fail ở `import tomllib` (`config_utils.py:5`) → nonzero → HALT. Fail-closed cả hai nhánh.

**Phát biểu prerequisite cho owner (nguyên văn đề xuất).** "Máy dự án chạy workflow BMAD cần: (1) `uv` (ghim 0.12.x) cài cố định, Homebrew hoặc `~/.local/bin` đều được; (2) một CPython ≥ 3.11 mà `uv` nhìn thấy trong môi trường đăng nhập của owner — ví dụ `uv python install 3.12` hoặc Homebrew `python@3.13`. Python 3.9.6 của Command Line Tools không đủ. Gateway tự đo và ghi đường dẫn + sha256 của `uv` và Python vào install report; Crew render bằng đúng interpreter đó, còn runtime (Claude Code/Codex) tự gọi `uv run` theo môi trường owner nên phải cùng thấy Python này." Máy hiện tại đã thỏa (uv thấy Homebrew 3.13.5 và uv-managed 3.12.12); lỗi S6a là do env executor che đi, không phải máy thiếu.

## 4. N1 — Tập đóng vs materialize A4

**Ruling: materialize tập con, suy từ definition, không đổi digest.**

Tập materialize = chính xác tập `checkClosure` đang bắt (`render-executor.ts:284-316`): `_bmad/scripts/{render_skill.py, config_utils.py}`, các layer trong `definition.render.layers` có mặt (`_bmad/config.toml` bắt buộc; `config.user.toml`, `custom/config.toml`, `custom/config.user.toml` tùy projection), thư mục rỗng `_bmad/render`, và `.claude/skills/bmad-build/**` đúng `selectedProjectionSha256`. Materializer đọc bytes từ projection root của registry (immutable), copy file thường (A4), rồi so sha256 với pin trước khi tiếp tục; executor xác minh lần nữa. **Một nguồn sự thật** (`definition.render`), không có danh sách thứ hai trong `workspace.ts`.

**Bằng chứng runtime không cần phần còn lại.**
- `grep memlog|resolve_config|resolve_customization|_bmad/scripts` trên `src/bmm-skills/ship/bmad-build/` của archive 6.12.0 đã pin: **một hit duy nhất** là lệnh render ở `SKILL.md:9`. Không file step nào gọi skill khác hay script khác.
- Ba script kia được tham chiếu bởi `bmad-prd`, `bmad-spec`, `bmad-architecture`, `bmad-ux`, `bmad-product-brief`, `bmad-sprint-planning`, `bmad-create-epics-and-stories`, agent `bmad-agent-pm` — không nằm trong tập A4 materialize. `.memlog.md` là input của `bmad-spec` (preflight :23), không phải của `bmad-build`.
- `render_skill.py` import stdlib + `config_utils` (`:9-23`); `config_utils.py` chỉ `tomllib`/`pathlib`. Không reader nào đọc `_bmad/custom/.gitignore` (nội dung `*.user.toml`, là vệ sinh git của installer cho `_bmad` được commit).
- Installer chính thức cũng nói rõ render chỉ phụ thuộc `uv` + `render_skill.py` (`tools/installer/core/uv-check.js:3-12`).

**Vì sao không chọn "tập đóng = toàn bộ pin".** Nó buộc definition mang thêm pin → `sha256` definition đổi → D2, S3b (install report `definitions`), S4 (`createRun` lookup) phải nghiệm thu lại, và mở rộng bề mặt code chạy trong renderer (`sys.path[0]`) mà không có lợi ích vận hành. Khi một phiên bản BMAD sau khiến `bmad-build` tham chiếu script khác, adapter sẽ đổi tập chọn theo pin mới và digest đổi **đúng lúc** đó.

**Rủi ro cần đo ở S6b (không phải ruling).** Nếu checkout của owner **track** `_bmad/` trong git, phase03 đã rename nó ra `excluded/` (`workspace.ts:495-504`) và runtime sẽ thấy tracked files bị xóa/đổi; materialize tập con làm `git status` của runtime bẩn thêm. Đề xuất mặc định: `git ls-files _bmad` trong owner checkout không rỗng → prepare BMAD từ chối với mã rõ (`BMAD_TRACKED_IN_CHECKOUT`), owner thấy được; lật nếu PM muốn hỗ trợ dự án đã commit `_bmad`.

## 5. Q3–Q7

- **Q3 (ai sở hữu luật tập đóng):** cả hai. Materializer (`workspace.ts`, phase03 transfer) **tạo** đúng tập từ `definition.render`; executor **xác minh** (đã có). Không copy luật sang file thứ ba. `inventory.ts:108` giữ `_bmad` là discovery directory; injected entries khai `_bmad/**` + `.claude/skills/bmad-build/**` theo pattern `.agents/skills` (`workspace.ts:505-515`) nhưng dạng copy, không symlink; `_bmad/render/**` (kể cả thư mục rỗng khi HALT) nằm trong khai báo.
- **Q4 (reconcile stage render):** owner = isolation workspace (cùng người reconcile `command-*`, `workspace.ts:196-236`). Record bền `render-{operationId}` trạng thái `reserved → pending → complete | unknown → deleted`, có `attemptId`, `stageIdentity`, `leader` (từ `.leader`), `receipt`. `cleanupWorkspace` và boot gateway: `pending` không receipt → `unknown`. **Ngưỡng chặn = 1**: bất kỳ `render-*` `unknown` trên root → mọi render mới trả `RENDER_RECONCILE_REQUIRED` (fail-closed; `unknown` là bất thường, không phải capacity). Giải tỏa qua lệnh `reconcile` của bridge (`ticket-command-bridge.ts:248,339`) với bằng chứng: `.leader` pid không còn và `KERN_PROC_SESSION` rỗng (helper thêm verb đọc `probe-session <pid>` nếu cần — tùy chọn, có thể để T7). Stage `timedOut` trong tree mode đã chứng minh session rỗng → reclaim ngay như HALT thường.
- **Q5 (owned root, tuần tự hóa):** dùng **isolation `operations`** (`workspace.ts:93`), không phải registry (registry là publication immutable và không có vòng đời attempt). Render chạy **trong `prepareWorkspace`**, sau exclusions/inject (`:496-515`) và **trước** audit `after` (`:511-519`), để `record.entries` chứa cả `_bmad/**` và generation; nhờ vậy `verify` tại release (`WORKSPACE_BYTES_CHANGED`, `:582`) không cần state mới. `store.transaction` (`atomic-records.ts` + `ProcessLock`) đã tuần tự hóa prepare/cleanup/render trong gateway; `flock .operations.guard` là hàng rào thứ hai cho tiến trình khác. N5: exit 20 trước fork → `EXECUTOR_BUSY`, executor trả `RENDER_OPERATION_BUSY` và **không** giữ stage. Timeout render mặc định 60 s giữ nguyên.
- **Q6 (chẩn đoán HALT):** **cho phép** gửi `log.sha256` + dòng đầu **và dòng cuối không rỗng** đã lọc (≤256 ASCII mỗi dòng) lên server trong `lastError`/timeline của attempt, dưới dạng dữ liệu (không đưa thẳng vào prompt LLM). Sửa R2/R3 của sanitizer trong S6b trước khi bật. Không gửi log đầy đủ.
- **Q7 (đường dẫn uv):** install report ghi **cả `path` (như owner cấu hình/đo) lẫn `realpath`**, sha256 trên realpath; symlink Homebrew chấp nhận; `witness.uvPath` = `path` đã ghi, `argv[0]` = realpath (đúng S6a M3/N4). Áp cùng luật cho `python`.
