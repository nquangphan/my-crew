## Smallest coherent producer-first release

1. **Captured binding and materialization contract, default deny.** A trusted host constructor, outside caller input, deep-freezes the exact project/checkout identity and binding revision, intended run/attempt scope, expected absolute project root, selected `SourcePin`/`ProjectionPin`, and the projection/renderer/uv identities. It resolves the pinned registry itself. It materializes `_bmad` and `.claude/skills/bmad-build` from the exact projection into a **host-owned run-scoped render root**; it never writes inside the registry publication. Before a positive path, PM must approve how this absolute root is the project root the real workflow will use, or prove an exact path mapping to the execution workspace. A scratch root with different `{project-root}` token semantics cannot silently stand in for the project. Current `IsolationWorkspace` verification would reject later injection, so host/isolation composition ownership must be reviewed; this report does not alter it.
2. **Current inputs and actual official execution.** Under a host-owned lifetime/identity guard, read and record presence plus raw SHA-256 of every central/customization layer listed above, the selected installed skill sources and renderer script, and current project binding. Re-read these inputs before returning a positive receipt so a mid-render change cannot inherit an old identity. Missing required layer, changed optional presence, alias/symlink/foreign file, mismatched pinned projection or stale binding denies. A separately reviewed bounded host executor must run the exact official `uv` argv once for this render operation in that owned root, with pinned executable bytes, private environment, bounded time/output/process closure and no ambient credential/network/model grant. Capture actual exit/stdout, the printed path, and the generation created or verified. No positive receipt is produced on nonzero, unavailable command, unknown child state or output-path mismatch. This execution budget is **not** authorized in the present static pass.
3. **Measured artifact reader.** The producer provides a capability closed over the immutable expected context, not a caller-selected path/hash or a `verified=true` flag. The adapter re-resolves requested source/projection against the captured pins, reads exact source/projection skill and renderer bytes, parses the raw `manifest.json` with exact schema/path rules, independently recomputes official renderer identity/generation path and hashes every declared output byte. It compares manifest project root to the host-captured expected root, `inputs.resolved_values` to values independently read from the current layers, and raw layer presence/byte hashes to the captured run context. Reads are confined to the owned generation and reject symlink/traversal/nonregular drift. The Crew definition digest also binds those raw layer hashes, generation manifest/output hashes and execution witness. A unit fake reader may test denials but cannot certify the production host.
4. **Durable gateway→server handoff before positive `createRun`.** Preserve public `loadDefinition(source,projection)` and `createRun(tx,proof,{rootTicketId,path,definitionSha256})` signatures. Bind the gateway factory to one captured project/render context and bind the server run factory to a trusted, durable `definitionSha256` lookup containing exact source/projection, selected skills, customization hash, actual render artifact identity, project/root binding and freshness. The caller hash is only a lookup key. The current `loadDefinition` return has only `{sha256,skills}`; SQL011 has `workflow_runs.rendered_artifact_id` UUID without a verified artifact FK and no typed definition-receipt table; no production transport or server lookup exists. PM must assign receipt persistence and authenticated handoff ownership (or a reviewed existing artifact producer) before a positive server path. Never call network/renderer/model under SQL locks. Until then BMAD and positive run creation remain denied.
